# F15 compatibility setting implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` for this small change. Steps use checkboxes to track verification.

**Goal:** Let existing cjson applications call `encode_keep_buffer` unchanged.

**Architecture:** Each codec stores the compatibility setting, defaulting to true. The setter/getter follows the pinned cjson API; it does not introduce or control a persistent encoding buffer. Current encoding and reader allocation lifetimes stay unchanged.

**Tech Stack:** LuaJIT, existing codec closures and setting validators, pinned native OpenResty verification image.

**Spec:** User decision to retain an inert migration parameter; F15 in `docs/design/cjson-compatibility-fixes.md`.

## Constraints and approaches

- A missing API forces migration changes. A real retained buffer adds unwanted memory behavior. The user chose the compatibility-only setting.
- Preserve normal/safe/new instance isolation, default true, getter/nil, boolean and native on/off inputs, argument validation and setter return values.
- Do not claim this option releases memory or changes allocation policy. No native changes, F16 implementation, commit or push in this task.

## Review focus

- Validate arguments before updating state, including extra arguments with leading nil.
- Safe configuration errors must still throw; safe conversion semantics stay unchanged.
- New codecs use defaults rather than inheriting the calling codec's setting.
- Both option values leave ordinary, lazy, eager, preload and reader output unchanged.
- Native option strings use the C-string prefix before an embedded NUL.
