# F18 strict userdata proxy implementation plan

> **For agentic workers:** Use `superpowers:subagent-driven-development`; the controller dispatches implementation and reviews. Follow the checkboxes below.

**Goal:** Add an optional userdata carrier that rejects unsafe native table operations while preserving current table/eager modes.

**Architecture:** Carry the selected proxy mode through source options and view ownership. Share logical nodes, source offsets and leases across both carriers; recognize own proxies before generic Lua type handling. Extend existing verification tools to observe the selected mode explicitly.

**Tech Stack:** LuaJIT/OpenResty, existing Rust source ABI, Busted, Python verification runners, pinned Docker runtime.

**Spec:** `docs/design/2026-11-02-strict-userdata-proxies.md`.

## Global constraints

- `proxy_mode = "table" | "userdata"`, default `"table"`; `lazyload=false` returns ordinary Lua values.
- Fork preserves the source carrier; assignment/insertion views use the destination carrier.
- Do not patch global builtins, silently materialize, weaken upstream expectations, alter memory thresholds, change the native ABI or implement F16.
- Preserve source/reader/fork/child lease and cancellation semantics, including GC without explicit close.
- Shared carrier metatables; do not allocate one metatable per proxy.
- Foreign userdata retains unsupported behavior; own userdata proxies must survive encoding with skip-unsupported enabled.
- Work only on the feature branch; no push/PR/merge. Keep a reviewable local implementation commit with an explicit file manifest.

## Review focus

1. Decoder `get` preserves NEED_INPUT before finish; successful get/repeated finish, detached children and array-remove results retain carrier and independent ownership.
2. Mixed plain/table/userdata containers and cross-codec forks are classified before unsupported-value filtering.
3. Preload/index policies and readers retain bounded source access rather than materializing to bridge types.
4. Abandoned/yielding operations, errors, duplicate close and GC do not leak, double release or cancel another holder.
5. Verification reports retain true userdata types, native exact failures and any memory-limit failures.
