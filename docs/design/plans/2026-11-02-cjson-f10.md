# F10 comment parsing implementation plan

> For agentic workers: use subagent-driven-development; parent supervises one coupled implementation task and final verification.

Goal: implement `decode_allow_comment` from `docs/design/cjson-compatibility-fixes.md` F10 against pinned `vendor/lua-cjson` without losing bounded source operation or valid output.

Architecture: add an isolated codec policy, propagate it to native source v2 and every late walker/rebuild, and parse comments with fixed-size incremental state. Flag comment-bearing source containers so output reconstructs only affected containers through existing bounded iterators; clean child spans remain reusable. This avoids materializing whole documents or retaining comment bodies. Prevent keep_origin whole-span reuse from bypassing comment removal. Retain legacy parse/source-v1 strict behavior.

Tech stack: LuaJIT/OpenResty Lua wrappers, Rust source v2 FFI, pinned native cjson oracle.

## Global Constraints

- Native default false. Setter/getter accepts boolean or exact on/off via existing settings validators, has atomic argument errors, independent defaults for module/new/safe. Snapshot at source/decoder creation, propagated to lazy reads, preload, eager rebuild/get/repeated finish and cross-codec/fork output.
- Support // through LF or EOF (CR alone does not end a native line comment), and non-nested /* ... */ wherever native accepts trivia. String contents and quoted keys never become comments. Reject comments inside numbers/literals rather than concatenating fragments. Match native errors/byte positions including unclosed comments and every feed split.
- Encoding always removes comment syntax in encode/reader/materialize-keep_origin paths, preserving literal string markers and unaffected raw spellings. Do not promise universal canonicalization. Actual comments inside a raw container must never bypass output policy; leading/trailing comments outside root are omitted naturally. Depth scans must not count brackets inside comments.
- Fixed-size comment/token state, no comment body retention, no whole-document materialization for stripping. Shared native structs remain ABI-compatible; additive mode bit/flag allowed, C zero modes and legacy APIs stay strict. All FFI exports preserve panic barriers.
- No runtime cjson parsing/encoding fallback. No changes to upstream expectations or adapter error normalization. Existing strict-number/control/UTF8 boundaries remain explicit. Preserve leases/cancellation and clean up errors without forced GC.
- Work only in existing worktree. No commits, branch changes, pushes or subagents by implementer/reviewer; parent integrates local main after verification. No whole-project rustfmt. No unrelated changes.

## Review Focus

Comment markers split at every boundary; comments with quotes, escapes, braces, invalid bytes and long bodies; native numeric/literal token boundaries and lexical-error precedence; lost policy/flags in resumed duplicate lookup/selected/eager rebuild; raw-span/origin/depth/cancellation bypasses.
