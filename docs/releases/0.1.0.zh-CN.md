# LeanJSON 0.1.0

这是 `lua-leanjson` fork 的首个正式版本，基于本项目的 `main` 分支。
Lua 模块名为 `leanjson`，原生库与 C ABI 使用 `leanjson` / `LEANJSON_*`
命名。上游 lua-qjson 的 0.1.0 属于另一项目的历史版本。

## 主要功能

- 通过 LuaJIT FFI 使用 Rust JSON 解码器，支持结构扫描与字段惰性访问。
- 可变对象/数组代理、独立的 `fork` 快照、显式资源所有权与有界编码 reader。
- 通过 `decode`、`decode_file` 和 `new_decoder` 支持内存、完成文件与增量输入，
  并提供 lazy、eager 和 preload 加载模式。
- OpenResty 请求体集成与有界 HTTP 输出，包含取消和资源清理行为。
- cjson 迁移设置与 `leanjson.safe` API；模块身份、惰性数组和 userdata
  载体的兼容差异已有明确记录。

## 安装

```sh
luarocks --lua-version=5.1 install lua-leanjson 0.1.0-1
```

LuaRocks 需要配置为 LuaJIT/OpenResty 的 Lua 5.1 模块目录。模块依赖
LuaJIT FFI，因此不支持 PUC Lua。

本版提供 Linux x86_64/amd64 与 ARM64/aarch64 预编译 rock，目标为
**glibc 2.35**，平台名称以 `luarocks config arch` 为准。安装二进制包
不需要 Rust。本版不提供 musl/Alpine 二进制包。源码安装需要 Rust/Cargo，
本次发布使用 Rust 1.90.0 构建。

发布制品包括 rockspec、源码 rock、两种 Linux 二进制 rock、构建信息、
中英文说明与 SHA-256 校验文件，均来自 `release-0.1` 上的 `v0.1.0` 提交。

## 迁移与已知限制

将 `require "qjson"` 改为 `require "leanjson"`，原生调用方需要针对更名后的
C ABI 重新编译。本版不安装 qjson 兼容模块。详见
[迁移指南](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.0/docs/migrating-from-cjson.md)。

本次发布接受已有性能限制：eager 解码的内存可能高于 cjson；文件或 preload
场景可能有更高 CPU 成本；同步文件操作会占用 OpenResty worker。
已测 lazy 内存结果仅对应报告中的工作负载，不构成通用内存或吞吐保证。

[完整验证报告](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.0/docs/verification/full-verification.md)
保留已有功能、HTTP、兼容性、内存和平台验证结果及各自基线。发布准备阶段
未重复执行全量套件，仅检查最终源码/二进制包、ABI 要求与隔离安装后的运行时 smoke。
