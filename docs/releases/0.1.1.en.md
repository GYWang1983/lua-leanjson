# LeanJSON 0.1.1

This patch release packages the latest `main` runtime code at
`aec40086846a7c1283498cae00310cb829fb8799`, merged into `release-0.1`, with
aligned version metadata and release packaging. LuaRocks version: `0.1.1-1`.

## Changes since 0.1.0

- Add source-backed immutable `ref(value[, path])` handles, independent
  leases and bounded serialization without materializing long strings.
- Add optional-path `len`, `exists` and `is_empty` queries for lazy/eager
  values, preserving presence and Lua truthiness semantics.
- Add reusable `compile_schema` plans and scan-time Schema assertions,
  budgeted structural string-boundary indexes and shared demand lookup caches.
  See the [supported Schema profile](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/schema-validation.md).
- Receive eligible unread fixed-length HTTP/1.1 request bodies through
  `ngx.req.socket()`. File and incremental sources retain input chunks in
  memory by default; `file_in_memory=false` retains the fd/spool-backed mode.
- Accelerate native scanning with a CJSON-derived string kernel, batch
  escaped-string processing, bounded scanner reservations and reused I/O buffers.
- Move string output length, escaping and raw-container depth checks into
  Rust. Readers reuse eligible raw source strings by default, reducing
  decode/re-encode work. `preserve_raw_strings=false` selects the previous
  reader spelling policy; `encode()` and `tostring()` retain their encoding
  behavior. Raw output can retain spellings such as `\/` and `\uXXXX` while
  preserving the JSON value.
- Include the complete Lua module set and the CJSON-derived code's license
  and attribution notices in installed rocks. Keep the published 0.1.0
  rockspec immutable and align Cargo/Lua identities to 0.1.1.

## Install and compatibility

```sh
luarocks --lua-version=5.1 install lua-leanjson 0.1.1-1
```

Configure LuaRocks for LuaJIT/OpenResty's Lua 5.1 tree. Prebuilt rocks cover
Linux x86_64/amd64 and ARM64/aarch64 on glibc 2.35, with no Rust or C compiler
needed at runtime. Source installation requires Rust/Cargo and a C99-capable
compiler; the release build uses Rust 1.90.0. PUC Lua and musl/Alpine binary
packages are outside this release's supported targets.

The release contains a source rock, both native binary rocks, the rockspec,
build metadata, English/Chinese notes and SHA-256 checksums. All final
artifacts come from the same `v0.1.1` commit.

## Verification and known limits

The existing [native serialization report](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/verification/cjson-memory-scanner.md)
and [Schema/index report](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/verification/source-index-schema-2026-11-03.md)
record correctness and performance evidence with their own source/environment
baselines. Release preparation reuses this evidence; fresh checks cover exact
source contents, both architectures, ELF/GLIBC requirements, isolated installed
LuaJIT/OpenResty smoke tests and public artifact checksums.

Existing validation boundaries remain visible: the native serialization
report records 60/66 strict paired-RSS passes, with six wide-scalar failures.
Eager/preload decoding and synchronous file work can cost more memory or CPU
than cjson. Workload-specific measurements do not establish a universal
latency, throughput or memory guarantee.

[CI run 42143017201](https://github.com/GYWang1983/lua-leanjson/actions/runs/42143017201)
has a lazy-fuzz assertion comparing negative and positive zero, and a selected
Memcheck failure whose recorded warning stack is in LuaJIT/cjson. These checks
are not reported as passing; their diagnostics are separate from the release
package/ABI smoke checks. Full validation is not repeated for this release.
