# LeanJSON 0.1.0

The first release of the `lua-leanjson` fork, based on the project's `main`
branch. The Lua module is `leanjson`; the native library and C ABI use the
`leanjson` / `LEANJSON_*` names. The upstream lua-qjson 0.1.0 release is a
separate project release.

## Highlights

- A Rust JSON decoder accessed through LuaJIT FFI, with structural scanning
  and lazy field access.
- Mutable object/array proxies, independent `fork` snapshots, explicit
  resource ownership, and bounded readers for encoded output.
- Memory, completed-file and incremental input through `decode`,
  `decode_file` and `new_decoder`, with lazy, eager and preload modes.
- OpenResty request-body integration and bounded HTTP output, including
  cancellation and cleanup behavior.
- cjson migration settings and a `leanjson.safe` API, with documented
  differences for module identity, lazy arrays and userdata carriers.

## Install

```sh
luarocks --lua-version=5.1 install lua-leanjson 0.1.0-1
```

Use LuaRocks configured for LuaJIT/OpenResty's Lua 5.1 module tree. PUC Lua
is not supported because the module requires LuaJIT FFI.

Precompiled Linux x86_64/amd64 and ARM64/aarch64 rocks target glibc 2.35.
The platform names come from `luarocks config arch`. Binary installations
need no Rust toolchain. This release does not supply musl/Alpine binaries.
Source installation requires Rust/Cargo (the release build uses Rust 1.90.0).

The release includes a rockspec, a source rock, both Linux binary rocks,
build metadata, these bilingual notes and SHA-256 checksums. All artifacts
are built from the `v0.1.0` commit on `release-0.1`.

## Migration and limitations

Change `require "qjson"` to `require "leanjson"` and rebuild native consumers
against the renamed C ABI. No `qjson` compatibility module is installed.
See [the migration guide](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.0/docs/migrating-from-cjson.md).

Performance limitations are accepted for this release: eager decoding can
use more memory than cjson, file/preload workloads can have higher CPU
costs, and synchronous file operations occupy an OpenResty worker. The
measured lazy-memory results are workload-specific, not a general memory
or throughput guarantee.

The [full verification report](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.0/docs/verification/full-verification.md)
records the existing functional, HTTP, compatibility, memory and platform
results and their individual baselines. Those full suites were not rerun
for release preparation. Release checks cover the exact source/binary
packages, ABI requirements and isolated installed-runtime smoke tests.
