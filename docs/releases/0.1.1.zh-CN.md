# LeanJSON 0.1.1

本补丁版本使用 `main` 最新运行时代码
`aec40086846a7c1283498cae00310cb829fb8799`，合入 `release-0.1` 后完成
版本号与发布制品准备。LuaRocks 版本为 `0.1.1-1`。

## 相比 0.1.0 的变化

- 新增 `ref(value[, path])` 不可变源码引用，支持独立 lease 和有界序列化，
  无需先物化长字符串。
- 新增支持可选路径的 `len`、`exists`、`is_empty` 查询，保留存在性与 Lua
  真值语义，适用于 lazy/eager 值。
- 新增可复用 `compile_schema` 与扫描阶段 Schema 断言、受预算约束的字符串
  边界索引和共享查询缓存。支持范围见
  [Schema 文档](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/schema-validation.md)。
- 符合条件的未读取固定长度 HTTP/1.1 请求体通过 `ngx.req.socket()` 接收。
  文件和增量来源默认在内存中保留输入块；设置 `file_in_memory=false`
  可继续使用 fd/spool 存储模式。
- 使用派生自 CJSON 的原生字符串扫描内核、批量转义处理、有界扫描器预分配
  和 I/O 缓冲复用，减少扫描与临时分配开销。
- 将字符串输出长度计算、转义和 raw 容器深度检查移到 Rust。reader 默认
  复用符合条件的源码字符串，减少解码再编码；设置 `preserve_raw_strings=false`
  可恢复旧 reader 拼写策略。`encode()` 和 `tostring()` 保持原编码行为。
  raw 输出可能保留 `\/`、`\uXXXX` 等原始拼写，JSON 值保持一致。
- 安装包包含完整 Lua 模块及 CJSON 派生代码的许可和署名文件；保留已发布
  0.1.0 rockspec 的原始字节，Cargo/Lua 版本统一为 0.1.1。

## 安装与兼容范围

```sh
luarocks --lua-version=5.1 install lua-leanjson 0.1.1-1
```

LuaRocks 需配置为 LuaJIT/OpenResty 的 Lua 5.1 模块目录。二进制包覆盖
Linux x86_64/amd64 和 ARM64/aarch64，目标为 glibc 2.35；运行时无需
Rust 或 C 编译器。源码安装需要 Rust/Cargo 和支持 C99 的编译器，本次发布
使用 Rust 1.90.0 构建。PUC Lua 和 musl/Alpine 二进制包不在本版支持范围。

制品包括源码 rock、两种原生二进制 rock、rockspec、构建信息、中英文说明
与 SHA-256 校验文件，最终制品均来自同一个 `v0.1.1` 提交。

## 验证与已知限制

已有[原生序列化报告](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/verification/cjson-memory-scanner.md)
及 [Schema/索引报告](https://github.com/GYWang1983/lua-leanjson/blob/v0.1.1/docs/verification/source-index-schema-2026-11-03.md)
记录各自源码与环境基线的正确性、性能证据。发布准备沿用这些结果；新执行的
检查覆盖精确源码、两种架构、ELF/GLIBC 要求、隔离安装后的 LuaJIT/OpenResty
smoke 与公开制品校验和。

现有验证边界继续保留：原生序列化报告的严格配对 RSS 为 60/66 通过，6 个
宽标量场景仍失败。eager/preload 和同步文件操作可能增加内存或 CPU 成本；
已测工作负载的结果不构成通用延迟、吞吐或内存保证。

[CI 运行 42143017201](https://github.com/GYWang1983/lua-leanjson/actions/runs/42143017201)
存在 lazy fuzz 比较负零与正零的断言失败，以及一项警告栈位于 LuaJIT/cjson
的 Memcheck 失败。这些检查仍按未通过记录，与本次制品和 ABI smoke 的结果
分别说明；本次发布不重复执行全量验证。
